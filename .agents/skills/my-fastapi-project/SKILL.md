# my-fastapi: проектные правила Codex

Скилл содержит самостоятельные соглашения разработки этого репозитория. Текущие дефекты, количество тестов и результаты линтера устанавливай по коду и фактически выполненным проверкам, а не по старым спискам задач.

## Контекст и границы

Это учебный backend-проект на Python 3.14, FastAPI, Pydantic v2, async SQLAlchemy 2.0, asyncpg, PostgreSQL и Alembic. Работай в существующей архитектуре Repository + Unit of Work. Версии сверяй с pyproject.toml, uv.lock и .python-version; не обновляй зависимости ради следования слову «современный».

Пользователь учится backend-разработке. Объясняй существенный механизм и причину решения на языке пользователя. По умолчанию действует учебный режим из AGENTS.md: читай и анализируй проект, показывай предлагаемый код в чате, не изменяй файлы и данные и не запускай команды, меняющие проект или БД. Обычная просьба реализовать или показать решение не отменяет этот режим. Применяй изменения только при явном разрешении пользователя на конкретные файлы/данные или явной отмене режима; соблюдай разрешённый объём. Прямая просьба обновить проектные инструкции разрешает изменение этих инструкций. Учебный план не даёт разрешения сразу реализовать все будущие этапы.

Сначала показывай подход, совместимый с текущим стеком, и объясняй его механизм. Давай основную рекомендацию; после уточнения пользователя пересматривай её и формулируй итоговое правило целиком, чтобы не оставлять противоречащие друг другу дополнения.

## Основные договорённости

- Используй uv для зависимостей и запуска: uv add / uv add --dev / uv sync / uv run. Не заменяй его прямым pip или Poetry.
- Сохраняй цепочку router → service → UoW → repository. Роутер не работает с ORM/session напрямую. Сервис возвращает Pydantic-схему, созданную до закрытия UoW.
- Одна публичная операция сервиса открывает свой async with uow. Commit явный; выход откатывает незакоммиченную работу и гарантирует закрытие сессии.
- Не вкладывай вызов другого сервиса, открывающего тот же UoW, в уже открытый UoW: FastAPI кэширует зависимость на запрос, повторный вход заменяет session.
- Разделяй ORM-модели и схемы ввода/вывода. Идентификатор действующего пользователя берётся из авторизации. Публичный ввод не получает поля привилегий; допустимые поля PATCH и их валидация определяются входной схемой. Сервис применяет model_dump(exclude_unset=True) через setattr без дублирующего списка полей; подробности — в правилах backend.
- Сохраняй существующие доменные исключения, их HTTP-статусы/заголовки и общий обработчик. Не вводи параллельную систему ошибок.
- Собственная БД в сервисных/API-тестах — настоящий отдельный PostgreSQL. Подмена внешнего провайдера допустима через его интерфейс; mock-последовательности внутренних вызовов не являются целью теста.
- Секреты не выводи в ответы, логи или примеры с реальными значениями. Используй .env.example для структуры настроек, .env остаётся приватным.

## Что читать для конкретной задачи

- При изменениях API, сервисов, ORM, конфигурации, миграций или авторизации прочитай [правила backend](references/backend.md), затем затронутый путь в текущем коде.
- При работе с логированием, HTTP middleware, метриками или хранением логов прочитай раздел «Логирование и наблюдаемость» в [правилах backend](references/backend.md), затем текущую настройку приложения.
- При изменении тестов или проверке backend-изменения прочитай [правила тестирования](references/testing.md), затем действующие conftest.py и тесты нужной функции.
- Для узкого объяснения читай только относящуюся к нему справку и код; не загружай весь проект без необходимости.

## Карта проекта

| Путь от корня репозитория | Назначение |
|---|---|
| app/main.py | FastAPI, lifespan, API-router, обработчики ошибок |
| app/api/deps.py | Composition root: UoW, сервисы, CurrentUserDep |
| app/api/v1/routes/ | HTTP-эндпоинты user, item, auth |
| app/core/config.py, security.py, uow.py | Настройки, JWT/пароли, транзакции |
| app/core/logging_config.py, middleware.py | Настройка логирования, HTTP-логи и замер длительности |
| app/db/ | DeclarativeBase, ORM-модели, Pydantic-схемы, engine/session factory |
| app/repositories/, app/services/ | Запросы и бизнес-логика |
| alembic/ | Миграции; env.py получает DSN из настроек |
| tests/unit/, tests/integration/ | Чистая логика и проверки с Postgres/HTTP |

## Работа и проверка

Перед редактированием посмотри git status и относящийся к задаче diff. Сохраняй изменения пользователя. Проверяй реальные возможности установленной версии библиотеки по документации, когда это существенно для решения. Уже разрешённый пользователем поиск документации не требует повторного согласования.

Команды из корня проекта для разрешённой реализации и проверки. В учебном режиме не запускай их автоматически, если они могут менять проект или данные:

~~~text
uv run fastapi dev
uv run uvicorn app.main:app --reload
uv run ruff check app tests
uv run ruff format --check app tests
uv run mypy app tests
uv run pytest tests/unit
uv run pytest
~~~

Если пользователь разрешил реализацию и проверки с изменением тестовой БД, после изменений backend-кода выполни подходящие целевые проверки и полный pytest с тестовым Postgres. При недоступной БД выполни разрешённые независимые проверки и явно сообщи, что интеграционные тесты не подтверждены. Не выдавай частичный прогон за полный. Учебные примеры в чате не требуют запуска тестов или изменений проекта.

Для изменения только инструкций/документации проверь формат, ссылки и фактические утверждения; запуск backend-тестов сам по себе не нужен. Не исправляй посторонние замечания линтера и не запускай массовое автоформатирование вне объёма задачи. Разделяй новые проблемы и существовавшие до изменения.

В результате кратко сообщи, что изменено или предложено, почему, какие проверки действительно выполнены и что осталось непроверенным. Если приводишь исполняемый пример, честно укажи, запускался ли он; не меняй проект или данные ради проверки примера в учебном режиме.
